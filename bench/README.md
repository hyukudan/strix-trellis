# Decode microkernel

> **Type:** design note — engineering record; may describe plans, candidates or experiments that are not part of the supported API.

`src/microbench.hip` is an independent implementation. It contains no upstream
implementation code. See [docs/SOURCES.md](../docs/SOURCES.md) for mathematical
sources, revisions and licenses.

Build on the test machine's CPU, without a GPU slot:

```sh
cd "<checkout>"
nice -n 10 /opt/rocm/core-10.1/bin/hipcc -O3 -std=c++17 --offload-arch=gfx1151 src/microbench.hip -o microbench
```

Measure from a dedicated directory synchronized across both test machines.
`tools/run_gpu_turn.sh` wraps a site-specific GPU queue script (not part of this
repository), with maintenance and site-specific quiet-hour checks:

```sh
bash tools/run_gpu_turn.sh --seconds 180 --maintenance-check "$PWD/tools/check_maintenance.sh" --queue-arg strix-trellis-micro -- "$PWD/microbench" 256 11
```

Modes: 0 per-tile load + checksum; 1 scalar state extraction + checksum;
2 scalar extraction + FP16 codebook + checksum; 3 grouped window extraction
+ codebook + checksum; 4 contiguous uint4 reads with a persistent grid.
`packed_GBs` counts ONLY compressed bytes read, in decimal GB. Modes 0–3 also
write 4 bytes per tile; mode 4 writes 16 KiB per sweep. The large volume forces
a memory traversal larger than the caches. One warm-up pass precedes each mode;
the median HIP event time is recorded. This is neither a counter-based DRAM
traffic measurement nor a GEMV benchmark.

Synthetic validation compares 257 tiles (65,792 states and FP16 results) per
combination against a scalar C++ oracle that extracts bits one by one and
computes the codebook with exact FP32 arithmetic before rounding to half.
It also checks equality between simple and grouped extraction. The real fixture
uses states and values generated by the independent Python reference and `--fixture`.

## First measurement (v1)

2026-10-20 18:28, queue label strix-trellis-micro-v1, on one of the test machines
(two Strix Halo systems). AMD Radeon 8060S, gfx1151, wave32; HIP reports
20 WGP = 40 physical RDNA CUs. ROCm hipcc 7.16.26385, clang 24.
256 MiB, 11 repetitions, raw data micro-v1.jsonl. V1 ran modes 0–2 and rates
2/3/4, with kernels identical to the current kernels in those modes.

mul1 decode: 52.5 / 71.0 / 107.5 GB/s for 2/3/4 bits.
Per-tile load control: 94.9 / 139.3 / 186.3 GB/s. This identifies
distribution/shuffle and checksum cost; it does NOT establish the EXL3 limit.
GEMV had not yet been measured.

## Index of later campaigns

The v1 microkernel above is historical. Later campaigns separate the core
from the complete operator: optimized mul1 decode with static ISA counts, cold
GEMV with activation staging (core only), WMMA M16/M64 with hot weights (core
only), a cold device-operator prefill sweep, the integrated V7 baseline
(80 fixtures), the complete cold API (67 cases, including validation, submit
and transforms) and HIP graph capture/replay. Their raw records are internal
and not published; current measured results are in the
[README](../README.md#measured-performance) and [CHANGELOG](../CHANGELOG.md).

```sh
python tools/summarize_api_bench.py api-linear.log --out results.csv
```

The exporter requires the final PASS and preserves unrounded RESULT figures.
The CSV does not replace correctness logs, hashes or methodology. Build the
API/graph benchmarks through CMake with `STRIX_TRELLIS_BUILD_BENCHMARKS=ON`.
All GPU programs run exclusively through the queue mechanism described in
[BUILD.md](../docs/BUILD.md) and their campaign's runner.
